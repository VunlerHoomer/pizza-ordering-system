# 接口与数据约定（待小组确认）

## 已有骨架

- `types.h` 提供金额（整数分）、顾客编号、订单编号及状态码。
- `input.h` 提供带范围验证的整数输入。
- `*_demo()` 为临时联调入口，返回 `APP_NOT_IMPLEMENTED`。
- `pricing_quote()` 为暂定定价接口，当前返回未实现，不产生报价。
- 尚未定义正式 Customer、Order、AppData 结构体；由相关负责人一起确认。

## 需要确认

| 项目 | 决定内容 | 负责人 |
|---|---|---|
| 顾客 | 编号、姓名、电话、登录凭据、余额、账户状态及长度限制 | B、D、E |
| 菜单 | 选项编号、名称、价格、启用状态；定价公式 | C、D、E |
| 订单 | 顾客、明细、成交时名称/单价、数量、总额、时间及状态 | D、E |
| 登录 | 权限、退出登录、停用账户及失败处理 | A、B |
| 文件 | 格式、版本、路径、容量和损坏处理 | E，全员确认 |

## 修改责任

B 修改账户资料；C 修改菜单和定价；D 负责充值和下单引起的余额、订单变化。
E 提供统一存储接口。交易成功必须保证余额和订单保存一致；失败策略由 D、E 共同实现与测试。
当前骨架没有实现这种一致性保证。

每个新接口记录：函数签名、输入约束、输出、错误码、是否修改状态、是否保存文件。
价格计算不进行输入输出、扣款或保存。旧订单保存成交信息，不通过当前菜单价格重新计算。
引用其他模块时 include 对方 `.h`，不要 include `.c`；正式程序只保留一个 `main()`。
