# E 的文件存储与销售统计实现说明

更新于 2026-11-09。工作分支为 `member-e-files`，实现位于 `file.c`。E 已完成模块测试与真实 C/E 联调，B、D 业务和 Windows 实机验收待完成。

## 1. 知识依据与设计选择

本次依据用户提供的《SOE103_课内知识范围_2026-11-09.md》，将已发布范围作为参考。用户已授权纯 C 实现、适度自学拓展，并确认开始开发。

| 部分 | 方法 | 范围依据 |
|---|---|---|
| 数据交接 | 固定结构体数组、结构体指针 | L6、L7 |
| 文件格式 | 每字段一行的版本化文本、逐成员读写 | L8 |
| 校验 | 字符数组、循环、范围检查、字符串比较 | L2–L6 |
| 文件 I/O | FILE、fopen、fgetc、fputc、fprintf、fflush、fclose、ferror | L8 |
| 临时文件与替换 | 临时文件、remove、rename | PhoneBook 方案 2 |
| 统计 | 遍历、分类累计、元分进位、字符柱条 | L3、L5 |
| 故障后停止保存 | 文件内 static 状态 | L4 |

核心代码采用 C90 写法，块开头声明变量，使用 `/* */` 注释。地址和未定义行为检查仅用于开发验证。

额外自学的部分为 `<limits.h>` 的 INT_MAX、`<errno.h>` 的错误区分、UTF-8 BOM 识别，以及 Windows 的 MoveFileExA 文件替换。Windows 的 C 运行库 rename 无法直接覆盖已有目标，因此用一个小适配函数完成备份和正式数据替换，避免先删除正式文件。Mac/Linux 使用 rename。文件均位于同一工作目录。

Windows API 依据见 [Microsoft MoveFileExA](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexa)。窗口界面和第三方依赖均无需配置。Windows 分支待实机验证，已有测试结果来自 Mac。

程序按单终端、单进程运行，使用期间由该进程独占这组数据文件。核心测试针对可检测的读写、关闭和替换错误。系统突然断电的物理持久性未做保证或实测。

## 2. 三个公共接口

| 接口 | 成功结果 | 失败结果 |
|---|---|---|
| loadData | 完整校验后更新共享数据并返回 1 | 保留调用方原数据并返回 0 |
| saveData | 完成保存或确认内容相同，返回 1 | 返回 0，本进程后续保存和重新加载都会拒绝 |
| showStatistics | 读取成交记录，显示累计统计 | 发现无效数据时说明原因 |

加载必须先成功，才允许保存。B、C、D 保存成功后才提示业务成功。保存失败时，由业务模块恢复本次内存修改并返回 -1，A 立即退出。

## 3. 文件格式 V1

文件以 UTF-8 保存。每个值独占一行，数字为十进制整数。读取接受 LF、CRLF、首行 UTF-8 BOM，以及 END 末行无换行。写出使用统一 LF 且无 BOM。

| 顺序 | 标记行 | 随后的内容 |
|---|---|---|
| 1 | PIZZA_SHOP_V1 | 文件头 |
| 2 | CUSTOMERS | 顾客数量，然后逐条顾客记录 |
| 3 | TYPES | 饼底数量，然后逐条饼底记录 |
| 4 | SIZES | 尺寸数量，然后逐条尺寸记录 |
| 5 | TOPPINGS | 配料数量，然后逐条配料记录 |
| 6 | ORDERS | 订单数量，然后逐条订单记录 |
| 7 | END | 完整文件的结束标记 |

每条顾客记录按以下顺序占 6 行。

```text
id
name
phone
password
balance
active
```

每条菜单选项按以下顺序占 4 行。

```text
id
name
price
active
```

每条订单按以下顺序占 11 行。

```text
id
customerId
typeId
sizeId
toppingId
typeName
sizeName
toppingName
quantity
unitPrice
total
```

完整初始实例见根目录 shop.example.txt。含空格、引号、竖线的名称可直接保存。字符串按原字节读写，长度以字节计。编码与字符显示由输入端和终端环境统一。

## 4. 字段校验及交接边界

| 数据 | E 实际接受的范围 |
|---|---|
| 顾客数量 | 0–100 |
| 每类菜单数量 | 0–10 |
| 订单数量 | 0–500 |
| 顾客及菜单编号 | 1–999999，同一集合内唯一 |
| 订单编号 | 1–INT_MAX，订单集合内唯一 |
| 姓名、电话、密码 | 非空，无控制字符，分别最多 49、19、31 字节 |
| 菜单名和成交名称 | 非空，无控制字符，最多 31 字节 |
| 启用标志 | 0 或 1，停用顾客的余额须为 0 |
| 账户余额 | 0–INT_MAX 分，业务层可采用更小上限 |
| 单项菜单价格 | 0–999999 分，与当前 C 的上限一致 |
| 成交单价 | 0–2999997 分 |
| 数量 | 1–10 |
| 订单总额 | 必须等于成交单价乘以数量 |

目标环境采用至少 32 位 int。名称和电话的进一步业务格式由 B 负责，例如允许的电话号码字符。E 负责存储完整性及长度检查。

各菜单类别分别编号，饼底 1、尺寸 1、配料 1 可以同时存在。订单引用的顾客和三类菜单选项必须保留，允许已经停用。旧订单使用其成交名称和单价，当前菜单改名或改价后仍可正确加载。

加载先解析到临时 ShopData，校验通过并成功关闭文件后再整体交付。拒绝部分记录、重复编号、未知版本、非法数值、超长字段、NUL 字节、缺失引用及 END 后的额外内容。

## 5. 首次启动与交付步骤

1. 在新开发目录中复制 shop.example.txt 为 shop.txt。已有业务数据时，先妥善保存原数据。
2. 在项目目录编译六个应用 C 文件。
3. 启动程序，验证进入首页菜单后输入 0 能正常退出。
4. 最终提交包直接放入准备好的 shop.txt，与 Windows exe、报告和 manual 一起交付。
5. 验收顾客和店长账户由 B 完成，并在报告中列出。

成功标志是老师解压提交包后即可启动，无需手动创建数据文件。当前本地已准备运行用 shop.txt，Git 中提交稳定的 shop.example.txt 模板。

缺文件、空文件或损坏时，程序明确报错并退出。发现上次中断留下的 shop.tmp 或 shop_backup.tmp 时，也先停止启动以便核查。

## 6. 保存的实际步骤

1. 校验内存数据，确认本进程曾成功加载，并检查不存在遗留临时文件。
2. 校验当前 shop.txt，确保它能够作为有效旧数据。
3. 将完整候选数据写入 shop.tmp，检查写入、刷新和关闭，再完整读取验证。
4. 若候选与 shop.txt 字节相同，删除本次候选并返回成功。这样正常退出的重复保存可保留上一份有用备份。
5. 将现有 shop.txt 复制到 shop_backup.tmp，检查复制、关闭、字节一致性和格式。
6. 用准备好的备份替换 shop_backup.txt。
7. 用候选文件替换 shop.txt，完成后返回 1。

正式文件整个准备阶段都保留。备份准备失败时，已有的正式文件和备份保留。备份替换成功但正式替换失败时，备份中保存的是旧的正式数据。候选和备份准备文件保留用于诊断，失败后的保存不会重试。

## 7. 文件故障的人工恢复

1. 关闭程序，复制当前 shop.txt、shop_backup.txt、shop.tmp、shop_backup.tmp 中存在的文件到独立留档文件夹。
2. 正式文件仍有效时，以正式文件作为已确认状态。正式文件损坏时，检查最后一次有效备份并将其复制为 shop.txt。
3. 保留留档后，移走工作目录中的两个 .tmp 文件。候选文件中的交易可能尚未确认，应结合订单和余额核对。
4. 重新启动，加载成功后核对账户余额、订单历史和销售统计，再继续操作。

成功标志是恢复后能完整加载并对账。恢复到较早备份会回到那次保存的状态，需要人工核对期间交易，因此采用人工确认。

## 8. 销售统计口径与显示

订单数统计成交记录笔数，披萨销量累计 quantity，销售额累计 total。充值金额保存在账户余额中。报表显示全部记录的累计结果，并按 toppingId 分组。

配料分组显示当前名称和启用状态，历史成交名称继续保存在订单中。停用配料的历史销量仍计入，零销量类别也列出。每类附一条按披萨数量归一化的 ASCII 柱条，最长 20 格。

最大累计销售额是 14,999,985,000 分。每笔先拆成元和分，然后逐笔累计和进位，避免把这个分总数直接存入一个 32 位 int。订单数最多 500，披萨数量最多 5000，累计元数最多 149,999,850。

## 9. 发给 B、D 的交接清单

### 与 B 确认

- 当前 Customer 和 ShopData 没有店长角色或凭据字段。请 B 确认店长身份来源，涉及持久化时先同步 project.h 和文件版本。
- 顾客账号在现有保留记录中唯一，停用记录继续占用编号。
- 顾客姓名、电话、密码和余额满足第 4 节范围。余额采用更小上限时告知 D。
- 注册、编辑、停用在调用 saveData 前完成内存变更，失败时恢复原记录及计数并返回 -1。
- 提供可用于最终 Windows 验收的顾客和店长账户。

### 与 D 确认

- 一条 Order 代表一笔已成交订单，quantity 为 1–10，成交名称和单价填写完整。
- 订单 id 唯一且为正数，保留历史引用，不物理删除被历史引用的记录。
- 写入单价乘数量之前先检查范围，E 会再次校验 total。
- 下单同步更新余额与订单，再保存共享数据。保存成功才提示成功；失败时回退余额、订单及计数并返回 -1。
- 充值成功后保存共享数据。保存失败回退余额并返回 -1。
- 用真实注册、充值、下单、重启链路联调，逐笔核对余额与统计。

### 与 A、C 同步

A 保留失败退出流程，并将初始化和恢复步骤写入最终 manual。C 保留菜单停用记录和编号、遵守现有价格上限，并确认配料分类使用当前名称。公共头文件变更先在组内协调。

独立复测时在一个新空文件夹运行测试。Mac 编译示例如下。

```sh
# 在项目根目录编译测试，测试仅有自己的 main
cc -std=c90 -Wall -Wextra -Wpedantic -Werror tests/test_file.c input.c account.c pizza.c -o /tmp/soe103-e-tests
# 创建隔离目录再运行，避免接触项目运行数据

cd /tmp/soe103-e-clean-check
/tmp/soe103-e-tests --empty-test-folder
```

成功标志为 `E TEST RESULTS: 188 assertions, 0 failures`。测试中会故意产生错误提示，用断言核对错误结果。使用过的测试目录应清理或换新目录后再运行。
